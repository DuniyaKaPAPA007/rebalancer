 Weekly Equal-Weight Rebalancer — Kaise Kaam Karti Hai (TXT VERSION)
================================================================================
One line: Trendlyne screener se watchlist.csv leke har rebalance pe portfolio
ko equal-weight (NAV / n) pe wapas lana — DhanHQ v2 se live, T+1 settlement
ke saath, bina wash-trade ke.

--------------------------------------------------------------------------------
1. OVERVIEW
--------------------------------------------------------------------------------
Purpose: Momentum/Golden-Cross jaise screener ke top-10 me har period equal
paisa lagana. Har rebalance pe jo bahar ho gaya EXIT, jo naya ENTRY, jo reh
gaya TRIM/TOPUP se exact weight pe.

Interface:
  Web: START-APP.bat -> http://127.0.0.1:8770 (Connect -> Watchlist -> Plan -> Execute)
  CLI: python -m rebalancer.cli plan -> execute --approve
Modes: paper (nakli 1cr, koi order nahi) vs live (Dhan credentials, haan/sab bech do)
Source of truth: Dhan holdings API. runs.db sirf audit.

--------------------------------------------------------------------------------
2. END-TO-END FLOW (Monthly EOM + T+1)
--------------------------------------------------------------------------------
Trendlyne CSV (25 rows)
 -> watchlist.py (SIMPLE/SCREENER/BACKTEST auto-detect)
 -> instruments.py (symbol/ISIN -> securityId via .cache/scrip_master.csv)
 -> Dhan API (holdings + fundlimit + marketfeed/quote + fallback yahoo/nse)
 -> planner.py:build_plan() [PURE: (holdings, ltp, watchlist, config) -> Plan]
 -> report.py (human text + cost)
 -> executor.py (SELL -> T+1 settle -> BUY)
 -> store.py (SQLite runs.db + plans/*.json)

Monthly kalender (settlement_T1: true):
  31st (SELL Day):
    - free_cash = Dhan se (50k)
    - SELL: OLD list se bahar + TRIM (overweight)
    - BUY is din sirf free_cash se, SELL ke 2L kal ayenge
      Warning: T+1 SETTLEMENT: Aaj BUY sirf free_cash se
    - Executor LIVE pe sirf SELL bhejta, BUY ko AWAITING_T1_BUY pe rokta (dry me dono preview)
  1st (BUY Day):
    - free_cash = 50k + sell settled 2L = 2.5L
    - Wahi watchlist se naya plan -> BUY (ENTRY/TOPUP) pure paise se
    - Executor ab BUY bhejta

settlement_T1:false (intraday) -> budget = free_cash + sell_proceeds same day (CNC ke liye galat).

--------------------------------------------------------------------------------
3. CORE LOGIC — planner.py (Pure Diff Engine)
--------------------------------------------------------------------------------
NAV = sum(holdings_qty * LTP) + free_cash

1. n = resolve_n(list_len) : n_stocks:auto = len-1 agar overflow on
   exit_rank_threshold:auto = n (strict top-n)
2. slice = investable / slots
   investable = target_equity - parked_keep_zone_value
   target_equity = min( NAV*(1-cash_reserve), deploy_budget )
   deploy_budget: all=NAV, pct=NAV*pct (0.6 ya 60 dono 60%), amount=fixed
3. slots = len(targets) if partial_list_mode:full (4 naam ->25% each) else n
4. SELL:
   EXIT: keep_zone aur overflow ke bahar -> sellable = min(total, available)
   TRIM: overweight aur drift=(cur-slice)/slice > band -> excess_qty=floor((cur-slice)/price) agar >min_trade (max(500, slice*3%)) warna Skipped
5. net_proceeds = sell_value*(1 - est_sell_cost) - DP*len(sells) (floor 0 if dust)
6. BUY: size_buys(scale)
   eff_slice = slice*scale, held_qty = total - trimmed
   drift >= -band aur held>0 -> skip (band ke andar)
   qty = floor(eff_slice - cur_val)/price agar >=min_trade
   Limit clamp circuit ke andar + tick 0.05
7. Cash shortage:
   budget = free_cash (T1) ya free_cash+proceeds (same-day)
   Pehle overflow (11th) bech ke fund (ceil exact, +1 overshoot fix), phir pro-rata scale *= budget/demand*0.9995 15 iter, best feasible rakho (pura discard nahi)
8. Overflow n+1: ov_room = investable - tgt_val_after (up to cap), held_val ka buy-cost nahi, need = target-held, buy_qty = floor(need / price*(1+cost))
9. _net_opposing: same symbol BUY 500+SELL200 -> net BUY 300 ek order, dust net BUY <min_trade skip, net SELL warn
10. Warnings: allocation adhura (buys < slots + skipped + S.No), concentration >25% -> cap, pricest slice <15 shares, stale LTP >5%, microcap <2000cr, narrow band <=10%, liquidity >1% traded_value
11. Minimum Capital min_capital_for_targets() — 8/10 ka fix:
    Har top-n ka price dekho: JSWDULUX 3118 -> 1 share ke liye 3118, IDEA 13.94 -> 500 ke liye 36 share = 501
    min_slice = max(price_i if price>=500 else ceil(500/price)*price) -> cheap stock decide karta hai
    Golden Cross top10: min_slice=3118, min_investable=31188, min_nav~31566 (1% reserve + 0.2% cost)
    Plan ke baad allocated = target_equity vs need compare -> allocated < need -> warning:
    CAPITAL KAM HAI: Top 10 me har ek me 1 valid order (500) ke liye min slice 3,118 -> total 31,188 + reserve. Aapne 10k allocate kiya -> 2 miss (8/10). Min NAV 31,566 chahiye.
    Web Plan tab me Stats me Minimum NAV + Min / stock + CAPITAL KAM / kaafi banner + per-stock CHENNPETRO 1393x1... detail, S.No se kaunsa chhuta clear.

Risk gates (penny pehle, phir cap):
  max_single_order 20L -> BLOCKED + suggest
  min_price 10 -> BUY skip only, SELL never
  max_turnover 85% churn (sell/NAV) pe, first deploy churn 0 -> pass
  qty==0 / limit invalid -> BLOCKED

Liquidation: watchlist ignore, sab SELL sellable tak, securityId+ltp both check.

--------------------------------------------------------------------------------
4. PRICE & CIRCUIT
--------------------------------------------------------------------------------
Primary: Dhan marketfeed/quote (1 req/s, chunk 500) -> CircuitInfo {ltp, upper, lower, prev_close, volume}
Fallback: fetch([yahoo,nse]) — yahoo per-thread Session (thread-safe), age>15m stale drop, NSE circuit enrich yahoo (has_circuit merge), upperCP/lowerCP ko intraHigh/Low se fallback nahi (false circuit fix).
Circuit use: at_upper = ltp >= upper*0.998 (0.2% tight), band = (upper-base)/base where base=prev_close (prev 0 -> None), liquidity o.value / traded_value.

--------------------------------------------------------------------------------
5. DHAN CLIENT
--------------------------------------------------------------------------------
Buckets: order 8/s (<10), data 4/s (<5), quote 0.9/s (<1), other 15/s
wait lock hold nahi (sleep bina reserve)
429 -> Retry-After + jitter, 500 -> DhanNoData only for /holdings with no data + holding/position keyword (HTML empty swallow nahi)

--------------------------------------------------------------------------------
6. EXECUTOR
--------------------------------------------------------------------------------
Age check BEFORE EXECUTING + TIMEOUT 30s WAL
SELL -> gap 20s -> BUY (T1 LIVE me SELL ke baad BUY skip + AWAITING_T1_BUY, dry me dono preview)
_fit_to_available_cash: limit_price se need (pehle ref_price kam), copy not mutate, affordable remaining/eff_price ke baad next cheaper buys try (pehle break)
_await_fills: poll after check (pehle sleep pehle), TERMINAL_OK = TRADED,COMPLETE,FILLED etc, filledQty multi-key, avg price multi-key, modify_to_market total qty try phir remaining, converted ko cancel nahi, _validate_order pre-flight (securityId>0, qty>0, price>0, tick)
reconcile: holdings avg_price fallback if ltp 0, nav + cash, drift vs slice.
S.No: sell/buy tables me 1,2,3
